      Done looks like: an `archive_07_validate.R` that runs `op_validate_meta()`
      and `op_validate_data()` per table, writes per-code counts to

## Downstream metadata (for obus)

obus publishes derived tables with no footer metadata. The agreed split: the
format and writer are opus's, the content for obus's own columns is obus's, and
the source `dict_sha256` travels with every derived table (obus `AGENTS.md`).

- [ ] **Export a writer, or at least the block schema**, expressible as DuckDB's
      `COPY … (FORMAT PARQUET, KV_METADATA {…})`, because obus streams from DuckDB
      and never materialises in R. If opus assembles the clause it owns the
      quoting (`DBI::dbQuoteString()`: the prose contains apostrophes).
- [ ] **Let the readers reach a non-Tier-1 file.** `op_dict()` and the others
      match `table` against `c("HH", "HL", "CA", "LT")` and `op_archive()` insists
      on a directory named `raw`. Relax both, or add path-based readers (the
      precedent is `op_describe_parquet()`).
- [ ] **Decide which blocks a derived table carries.** `dict` and `provenance`
      clearly; `sentinels` probably not (obus scrubs nothing); `coverage` and
      `known_issues` need a call; a machine-readable grain belongs somewhere.
- [ ] **The provenance contract:** a derived table names the source archive's
      `dict_sha256`, `opus_version` and `opus_git_sha`.
